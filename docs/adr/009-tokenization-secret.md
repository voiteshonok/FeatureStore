# ADR-009: Tokenization secret

- **Status:** Accepted
- **Date:** 2026-11-07
- **Related:** US-1.2, NFR-8, PCI DSS v4.0.1 Req. 3; ADR-000

## Context

Ingestion replaces the PAN with `card_token = HMAC-SHA-256(pan, key)`. The key must
stay secret, the token must be deterministic (the same card always maps to the same
token), and the system runs on one server without external services.

## Decision

- One system-wide key of 32 random bytes, generated by `make secret` into
  `secrets/hmac_key` and passed to ingestion as a Docker secret. `.env` and `secrets/`
  are never committed.
- **Key rotation is not supported.** Changing the key changes every token and breaks
  window history. This is a documented limitation.
- The ingestion logger has a filter that masks any run of 13–19 digits.
- Tests: one card gives one token; different cards give different tokens; the PAN
  scanner finds 0 PANs in stores and logs (Luhn-checked to avoid false positives).

## Alternatives considered

- **Vault or a cloud KMS** — correct for production, but an extra component and, for
  KMS, an external service in the scoring path.

## Consequences

- Simple and sufficient for a single-server deployment.
- Key management and rotation (PCI DSS Req. 3.6–3.7) are named as future work.
