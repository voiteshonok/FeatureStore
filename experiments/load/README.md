# Feature read load (k6)

One scenario measures feature-read latency for three targets with the same
request mix: **direct** features-api (`:8001`), **gateway** (`:8080` with
`X-API-Key`), and SQL **baseline** (`:8003`).

Ingestion load is **not** generated by k6 — keep the simulator at 200 TPS for
the whole run. Without write traffic, K1 is understated and K2 is not observed.

## Install k6

Linux (Debian/Ubuntu), Grafana package:

```bash
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg \
  --keyserver hkp://keyserver.ubuntu.com:80 \
  --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" \
  | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

Other platforms: https://grafana.com/docs/k6/latest/set-up/install-k6/

## Stand preparation

From the repository root:

```bash
make secret
make up
# optional, for TARGET=baseline only:
make baseline-up
# warm windows (optional but recommended before a 10m measurement):
make backfill
# write load for the duration of the k6 run (default 200 TPS / 10m):
docker compose -f infra/docker-compose.yml --profile sim up simulator
```

Harvest HMAC tokens already on `transactions.raw` (Kafka topic on
`localhost:29092`). k6 cannot compute them; requests for unknown cards only
exercise the default path.

```bash
uv run python experiments/load/sample_tokens.py
# → experiments/load/tokens.json
```

## Three targets

Defaults: `RATE=200`, `DURATION=10m`, latency thresholds p99 < 20 ms and
p50 < 5 ms, error rate < 0.1%. Baseline disables latency thresholds (expected
to miss K1). `HOST` and `API_KEY` come from the environment.

### Direct (`:8001`)

```bash
OUT=experiments/load/runs/$(date -u +%Y%m%dT%H%M%SZ)-direct
mkdir -p "$OUT"
{
  echo "TARGET=direct"
  echo "HOST=${HOST:-localhost}"
  echo "RATE=${RATE:-200}"
  echo "DURATION=${DURATION:-10m}"
} > "$OUT/run.env"
k6 run -e TARGET=direct -e HOST="${HOST:-localhost}" \
  --summary-export="$OUT/summary.json" experiments/load/features.js
```

### Gateway (`:8080`)

ADR-008 caps each client at **100 requests/s**. At 200 RPS that yields ~50%
**429** unless the limit is raised for the run.

```bash
# in infra/.env (or the shell env used by compose), then recreate gateway:
# GATEWAY_RATE_LIMIT=400/second
docker compose -f infra/docker-compose.yml up -d --wait gateway

OUT=experiments/load/runs/$(date -u +%Y%m%dT%H%M%SZ)-gateway
mkdir -p "$OUT"
{
  echo "TARGET=gateway"
  echo "HOST=${HOST:-localhost}"
  echo "RATE=${RATE:-200}"
  echo "DURATION=${DURATION:-10m}"
  echo "GATEWAY_RATE_LIMIT=${GATEWAY_RATE_LIMIT:-400/second}"
  echo "API_KEY=${API_KEY:-dev-scoring-key}"
} > "$OUT/run.env"
k6 run -e TARGET=gateway -e HOST="${HOST:-localhost}" \
  -e API_KEY="${API_KEY:-dev-scoring-key}" \
  --summary-export="$OUT/summary.json" experiments/load/features.js
```

Dev key matches `infra/.env.example` (`scoring:dev-scoring-key`).

### Baseline (`:8003`)

Requires `make baseline-up`. Latency thresholds are off; summary still records
the AS-IS numbers for the thesis comparison.

```bash
OUT=experiments/load/runs/$(date -u +%Y%m%dT%H%M%SZ)-baseline
mkdir -p "$OUT"
{
  echo "TARGET=baseline"
  echo "HOST=${HOST:-localhost}"
  echo "RATE=${RATE:-200}"
  echo "DURATION=${DURATION:-10m}"
} > "$OUT/run.env"
k6 run -e TARGET=baseline -e HOST="${HOST:-localhost}" \
  --summary-export="$OUT/summary.json" experiments/load/features.js
```

After a 200 RPS run, confirm `dropped_iterations` is 0 in the k6 summary (VU
headroom is sized for that rate). A gateway run must not show 429 responses.

## Remote machine

Point `HOST` at the lab host. Open the read ports you need (`8001`, `8080`,
`8003`). Sample tokens on a host that can reach Kafka (`29092`), or copy
`tokens.json` to the load generator. Use the same API key as `GATEWAY_API_KEYS`
on that stand.

```bash
HOST=192.0.2.10 API_KEY=dev-scoring-key \
  k6 run -e TARGET=gateway -e HOST="$HOST" -e API_KEY="$API_KEY" \
  --summary-export=experiments/load/runs/remote-gateway/summary.json \
  experiments/load/features.js
```

## Smoke (nightly e2e)

`SMOKE=1` forces 20 RPS for 15 s and disables latency thresholds. Checks
(status 200, full catalog, each feature has `status`) still fail the process:

```bash
SMOKE=1 k6 run -e TARGET=direct -e HOST=localhost -e SMOKE=1 \
  --summary-export=experiments/load/runs/smoke/summary.json \
  experiments/load/features.js
```

## Artifacts

`tokens.json` and `experiments/load/runs/` are gitignored. By default k6 reads
`tokens.json` next to `features.js` (`open()` is script-relative). Pass an
absolute `TOKENS_FILE` to override.
